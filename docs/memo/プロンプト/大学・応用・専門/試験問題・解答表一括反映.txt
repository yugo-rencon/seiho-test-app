添付または指定された試験問題PDFと解答表を正本として、生命保険大学課程・専門課程・応用課程の指定Vueファイルに、設問タイトル・正解表示・確認済みの `rev` をまとめて反映してください。

この手順は、次の3課程で共用する。

- 大学課程: `resources/js/Pages/Daigaku/Tests/<科目>/<ファイル名>.vue`
- 専門課程: `resources/js/Pages/Senmon/Tests/<ファイル名>.vue`
- 応用課程: `resources/js/Pages/Ouyou/Tests/<ファイル名>.vue`

## この3課程の問題構成

通常は49問・37管理単位で構成される。問題番号・コンポーネントは必ず対象Vueファイルで照合すること。

| 問題番号 | Vueコンポーネント | 内容 | 進捗上の数え方 |
|---|---|---|---:|
| 1〜24 | `QuestionTemp1`（計算問題などは `QuestionTemp4` の場合あり） | 4肢から正しいものを選ぶ問題 | `rev` は付けない |
| 25〜29 | `QuestionTemp3` | 語群から選ぶ穴埋め問題 | 5問で1単位 |
| 30〜34 | `QuestionTemp3` | 語群から選ぶ穴埋め問題 | 5問で1単位 |
| 35〜39 | `QuestionTemp3` | 語群から選ぶ穴埋め問題 | 5問で1単位 |
| 40〜49 | `QuestionTemp2` | 正誤・訂正問題 | 1問ずつ |

`QuestionTemp4` は計算問題などの個別問題で、問1〜24の途中にも置かれる。配列の位置ではなく、`questionNumber`、`questionRange`、各 item の末尾コメント（例: `//40`）で問題番号を確定する。

## 既存データの扱い

- `questionTitle`、`contents`、`labels`、`items`、`rev` がすでに入っていても、完了扱いで読み飛ばさない。過去の入力・確認結果として扱い、PDFと解答表に照らして再チェックする。
- 既存内容とPDFが一致した場合も、確認済みとして `rev` を重複追加せず、必要なら作業日に更新する。
- 不一致はPDF・解答表を優先して修正する。PDFのOCR結果だけで確定せず、該当ページを目視確認する。
- 指定範囲外の問題文、解説、関連問題、レイアウトは変更しない。

## 作業手順

### 1. 編集前の照合表を作る

PDFから、問1〜49について次を問題番号単位で整理する。

- 設問タイトル
- 解答表の正解記号または正誤
- 語群・選択肢の文言（必要な範囲）
- Vue内の対応コンポーネント・`questionTitle`・`label`・`content`

`questionTitle` は見出しとして簡潔に入力する。PDF上の設問タイトルが末尾の「について」で終わる場合は、その「について」を省略する（例: `株式会社の機関について` → `株式会社の機関`）。ただし、「〜についての」のようにタイトル途中に含まれる表現は省略しない。

問25〜39と問40〜49は配列の並びだけで対応付けない。`questionRange` と item末尾の問題番号コメントを照合する。問40〜49は前後の問題と値が1つずれていないことを必ず確認する。

### 2. 問1〜24を反映する

- `QuestionTemp1` の `questionTitle` に、PDFの設問タイトルを設定する。
- 解答表のア・イ・ウ・エと `contents` の配列位置を対応付ける。正解の位置は `正しい` とし、他の選択肢はPDFの正しい訂正・解説内容を維持または補完する。
- すでに具体的な訂正文や解説がある `contents` を、解答記号だけを理由に空欄や `正しい` で上書きしない。
- 問1〜24には `rev` を付けない。既存の `rev` がある場合は削除する。`正しい` を入力した `contents` の行では末尾の `//p` も削除し、空欄・訂正内容の行の `//p` は残す。
- 計算問題等で `QuestionTemp4` が使われている場合も、各 `contents` オブジェクトの `questionTitle`・`answer`・`labels` をPDFと解答表で照合する。選択記号（`labels`）だけを数値・計算結果の `answer` に置き換えない。問1〜24にある `QuestionTemp4` にも `rev` は付けない。

### 3. 問25〜39を反映する

- 各 `QuestionTemp3` の `questionRange`（通常は25〜29、30〜34、35〜39）とPDFの空欄番号を照合する。
- `questionTitle` にその5問ブロックの題名を入力する。
- PDFの語群から、解答表の記号に対応する語句を確認する。
- `labels` には問題番号ごとの解答記号を、`contents` にはその記号に対応する語句を同じ添字で入れる。
- 5つすべてについて「問題番号 / 解答記号 / 語句 / Vueのlabels / Vueのcontents」を突合する。語群の掲載順だけから推測しない。
- `contents` 配列先頭に、値の前の独立行として `// rev: YYYY-MM-DD 確認済み` を置く。1つの `QuestionTemp3` の `rev` は、その範囲の5問を確認したことを表す。

### 4. 問40〜49を反映する

- `QuestionTemp2` の `items` を、各オブジェクト末尾の `//40`〜`//49` を正本として問題番号に対応付ける。
- 各 item の `questionTitle` をPDFの設問タイトルに設定する。
- 解答表で「正」の問題は `content: '正しい'` とする。「誤」の問題は `content: ''` の空欄のままとし、訂正内容は入力・保持しない。
- 「誤」の item に既存の具体的な訂正内容がある場合も、空欄にする。
- `// rev: YYYY-MM-DD 確認済み` は、`content: '正しい'` を入力した「正」の item にだけ、itemオブジェクトの先頭（`questionTitle` の前）の独立行として置く。「誤」の item には付けない。`正しい` を入力した item の末尾の `//p` は削除し、空欄の item の `//p` は残す。既存の `rev` がある場合はこのルールに合わせて削除する。

## 検証

1. 解答表を目視確認し、問1〜49すべての番号と正解を読み取る。OCRだけでは確定しない。
2. 問25〜39は各5問、問40〜49は各1問を、PDFの設問番号・タイトル・語群／正誤と再照合する。
3. `QuestionTemp4` を含む場合は、問題番号が連番どおりであること、選択記号と計算結果を混同していないことを確認する。
4. 対応する進捗表を更新する。存在しない場合は、同じ課程の他科目（例: `Kigyo-progress.md`）と同一の見出し・集計ルール・「全体 / ファイル別 / 未完了一覧」の表形式に合わせて `docs/memo/<課程名>/<科目名>-progress.md` を新規作成する。集計は `// rev` を基準とし、問1〜24は `rev` を付けないため未完了、`QuestionTemp3` は5問、`QuestionTemp2` は「正」で `rev` がある item を1問として数える。通常の総問題数は49問、進捗表上の最大管理単位は37である。
5. 最後に `git diff --check -- <対象Vueファイル> <進捗表>` を実行する。進捗表を更新しない場合も、対象Vueファイルに対して実行する。

`YYYY-MM-DD` には作業日を入れる。
