添付または指定された試験問題PDFおよび解答表をもとに、指定されたVueファイルの `questionTitle`・解答記号・正解の表示内容を反映し、確認済みの `rev` と進捗表を更新してください。

対象:
- resources/js/Pages/Tests/<科目>/<ファイル名>.vue
- docs/memo/生命保険講座/進捗表/<科目>-progress.md

既存データの扱い:
- 対象範囲にすでに `questionTitle`・`content`・`label`・`rev` が入っていても、完了済みとして読み飛ばさない。既存の内容は仮入力または過去の確認結果として扱い、PDFを正本として設問番号ごとに再チェックする。
- PDFと既存内容が一致する場合でも、再照合したことを確認する。`rev` は重複追加せず、既存の確認日を必要に応じて作業日に更新する。
- PDFと既存内容が異なる場合は、PDFの記載を優先して修正する。特に問41〜50は、前後の問題からの値ずれがないかを必ず確認する。

作業手順:

1. 対象のPDFを確認する
   - PDF内の設問番号と設問タイトル（例：`［会計公準］`）を抽出する。
   - PDFのOCR結果に文字化けや誤変換がある場合は、設問本文と一般的な用語に照らして正しい表記を確認する。
   - 問1〜20の語群と、問41〜50の各設問の選択肢をPDFから確認する。画像の掲載順や左右配置だけで対応付けない。
   - 解答表（問題PDF内の解答一覧ページまたは別添の解答表）がある場合は、問1〜50の正解をすべて抽出する。解答一覧は、問31〜50も含めて画像で確認し、OCRだけで確定しない。
   - 編集前に、解答表とVueの対応表を作る。少なくとも問41〜50は「問題番号 / 解答表の記号 / PDFの設問タイトル / VueのquestionTitle / label / 反映するcontent」を並べ、番号ずれがないことを確認する。

2. 問1〜20を反映する
   - `QuestionTemp3` の `questionTitle` に、対応する大項目のタイトルを入力する。
   - 1つの `QuestionTemp3` が複数問を含むため、PDFの空欄番号の範囲（例：`[1]〜[5]`）と対応を確認する。
   - PDFに①・②などの区分がある場合は、タイトルにもそのまま含める。
   - PDFの語群から各 `labels` の記号に対応する語句を特定し、同じ順序で `contents` に入力する。
   - 解答表がある場合は、問1〜20の解答記号を対応する `labels` に反映し、語群から取得した `contents` と突合する。
   - `contents` 配列の先頭に `// rev: YYYY-MM-DD 確認済み` を追加する。すでにある場合は重複して追加しない。

3. 問21〜30を反映する
   - 各 `QuestionTemp1` の `questionTitle` に、設問番号ごとのタイトルを入力する。
   - 解答表がある場合は、各問の正解位置（ア・イ・ウ）と `contents` 配列の位置を照合する。
   - `contents` が解答表反映用の空欄テンプレートである場合は、問21〜25は指定位置だけ、問26〜30は指定位置以外の2箇所だけを `正しい` にする。`正しい` を入力した行の末尾にある `//p` は削除し、空欄の行の `//p` は残す。
   - すでに具体的な解答内容・解説文が入っている場合は、解答表との照合に使うだけで、`正しい` や空欄で上書きしない。

4. 問31〜50を反映する
   - `QuestionTemp2` の `items` にある各 `questionTitle` に、設問番号ごとのタイトルを入力する。
   - 解答表がある場合、問31〜40は「正」の問題だけ `content` を `正しい` にする。すでに具体的な解答内容が入っている場合は上書きせず、正誤の照合に使う。
   - 問31〜40は、解答表で「正」の問題だけ各 `items` オブジェクトの先頭に `// rev: YYYY-MM-DD 確認済み` を追加する。「誤」の問題には `rev` を付けない。
   - 問41〜50は、PDFの設問タイトルとVueの `questionTitle` を問題ごとに照合してから、解答表の記号を各 item の `label` に反映する。解答表がない場合は、PDF本文から正解記号を確定する。
   - `label` の記号に対応する選択肢文言を、同じ問題の `content` に入力する。
   - 選択肢が `A-` または `B-` で始まる場合、`content` には接頭辞を含めず、文言だけを入力する。
   - `label` が `オ`（「C（A・Bともに正しい）」）の場合は、`content` を空欄のままにする。
   - 問41〜50の各 `items` オブジェクトの先頭に `// rev: YYYY-MM-DD 確認済み` を追加する。すでにある場合は重複して追加しない。

注意:
- 問1〜50の解答表を反映する際は、解答表の問題番号とVue内のコメント（例: `//31`）を1問ずつ突合する。配列の位置やPDFの左右配置だけを根拠に対応付けない。
- 問21〜30の解答表反映は、既存の `contents` の表現形式を確認してから行う。具体的な解答内容を持つファイルを空欄や `正しい` だけの表示に置き換えない。
- 編集後に、問41〜50の `questionTitle`・`label`・`content` を問題ごとに再確認し、前後の問題から値をずらしていないことを確認する。
- `QuestionTemp2` の問題番号は、各 `items` オブジェクト末尾の `//問題番号` を正本として確認する。配列内の位置だけで問題番号を判断しない。
- 指定されたVueファイルと進捗表だけを変更する。
- 指定範囲以外の問題文、既存の解答・解説・コメントは変更しない。
- `YYYY-MM-DD` には作業日を入れる。
- 問題番号とタイトルの対応を、PDFの前後のページも含めて確認する。
- 進捗表では、`// rev` がある問題を完了として集計する。`QuestionTemp3` の `rev` は5問、`QuestionTemp2` の各 `items` の `rev` は1問として数え、更新日時・全体/対象ファイルの進捗・未完了一覧を更新する。
- 最後に `git diff --check -- <対象Vueファイル> <進捗表>` を実行する。
