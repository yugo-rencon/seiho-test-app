対象:
- resources/js/Pages/Tests/Keiri/<ファイル名>.vue
- docs/memo/生命保険講座/Keiri-progress.md

## 生命保険計理の問題構成

生命保険計理は、次の構成を前提とする。

| PDF上の問題番号 | Vueコンポーネント | 内容 | Vue上のまとまり | 進捗上の数え方 |
|---|---|---|---|---:|
| 問1〜10 | `QuestionTemp4` | 計算問題 | 通常は問1〜5、問6〜10の2ブロック | 各 item を1問 |
| 問11〜20 | `QuestionTemp3` | 語群から選ぶ穴埋め問題 | 通常は問11〜15、問16〜20の2つの大問 | 各大問を1問 |
| 問21〜24 | `QuestionTemp4` | 計算問題 | 通常は4問を1ブロック | 各 item を1問 |
| 問25〜30 | `QuestionTemp1` | 3肢から選ぶ問題 | 1問ずつ | 各問を1問 |
| 問31〜50 | `QuestionTemp2` | 正誤問題・組み合わせ問題 | 通常は20問を1ブロック | 各 item を1問 |

通常は、PDF上の50問を進捗表では42管理単位として数える。

- 問1〜10: 10単位
- 問11〜20: 2単位
- 問21〜24: 4単位
- 問25〜30: 6単位
- 問31〜50: 20単位

ただし、年度・フォームによって問題構成や管理単位数が異なる場合がある。既存Vueの `questionNumber`、各itemの問題番号コメント、PDFの設問番号を優先し、42単位になるよう機械的に補正しない。

## 既存データの扱い

- 対象範囲に `questionTitle`、`choiceOptions`、`contents`、`labels`、`items`、`rev` が入っていても、完了済みとして読み飛ばさない。既存内容は仮入力または過去の確認結果として扱い、PDFと解答表を正本として再確認する。
- PDFと既存内容が一致する場合も、再照合したことを確認する。`rev` は重複追加せず、必要に応じて確認日を作業日に更新する。
- PDFと既存内容が異なる場合は、PDFと解答表の記載を優先して修正する。
- OCRだけで数値、記号、数式を確定しない。特に小数点、桁区切り、指数、丸め単位、ア・イ・ウ等の選択記号はPDF画像を目視確認する。
- 指定範囲外の問題文、既存の解答・解説、コメント、レイアウト、学習モード関連の設定は変更しない。
- ただし問25〜30および問31〜40の未完成箇所は、以下の専用ルールを優先する。別途、解説作成を明示的に依頼されていない限り、訂正内容や解説を作成・流用せず、空欄と `//p` に戻す。

## 作業手順

### 1. 編集前の対応表を作る

PDFと解答表から、問1〜50について次を問題番号ごとに整理する。

- PDF上の問題番号
- 設問タイトル
- 解答表の正解記号
- 正解記号に対応する選択肢の文言または計算結果
- Vue内の対応コンポーネント
- Vue内の `questionTitle`、`label`、`answer`、`content`

配列の位置だけで問題番号を決めない。次を組み合わせて対応を確定する。

- コンポーネントの `questionNumber`
- `contents` または `items` 付近の問題番号コメント（例: `// 問21`、`//31`）
- `labels` の末尾コメント（例: `//21`）
- PDF本文の設問番号

`QuestionTemp3` の `questionNumber` は画面上の大問番号であり、PDF上の先頭問題番号とは一致しない場合がある。問11〜15、問16〜20の対応は、`contents`、`labels` の問題番号コメントとPDFの空欄番号で確認する。

### 2. 問1〜10の `QuestionTemp4` を反映する

- 通常は問1〜5と問6〜10の2つの `QuestionTemp4` に分かれている。各 `contents` オブジェクトをPDF上の1問として扱う。
- 各itemの `questionTitle` に、対応する設問の簡潔な題名を入力する。
- PDFの選択肢を `choiceOptions` に、掲載順と記号を保って入力する。問題ごとに選択肢が異なる構成では `choiceOptionsByQuestion` を使用し、既存Vueの形式を維持する。
- 解答表の正解記号を同じ問題番号の `labels` に入力する。
- `answer` には正解記号ではなく、その記号に対応する選択肢の文言または計算結果を入力する。単位が選択肢に含まれる場合は、PDFおよび既存表示形式に合わせる。
- `labels` と `contents` は同じ添字同士が同じ問題になることを確認する。共有語群・共有選択肢の掲載順だけから正解を推測しない。
- `explanation` は確認・修正・追加・削除をせず、テンプレートにある内容をそのまま維持する。PDFの設問条件と一致していなくても、この一括反映作業では変更しない。
- 問1〜10は `explanation` を確認しないため、この一括反映では未完成として扱い、各itemに `// rev` を付けない。既存の `rev` がある場合も削除する。

### 3. 問11〜20の `QuestionTemp3` を反映する

- 通常は問11〜15と問16〜20の2つの大問で構成される。
- `questionTitle` に各大問の題名を入力する。
- PDFの語群を `choiceOptions` に、記号と文言を対応させて入力する。
- 解答表の問11〜20の解答記号を、対応する大問の `labels` に問題番号順で入力する。
- `contents` には、各 `labels` の記号に対応する語句を同じ順序で入力する。
- 5問すべてについて「問題番号 / 解答記号 / 語句 / Vueのlabels / Vueのcontents」を照合する。語群の掲載順だけで対応付けない。
- 5問すべての確認が完了した大問は、`contents` 配列の先頭に `// rev: YYYY-MM-DD 確認済み` を置く。1つの `QuestionTemp3` の `rev` は進捗上の1管理単位として数える。

### 4. 問21〜24の `QuestionTemp4` を反映する

- 各 `contents` オブジェクトを1問として扱い、問1〜10と同じ方法で `questionTitle`、選択肢、`labels`、`answer` を照合する。`explanation` は変更しない。
- 問題ごとに選択肢が異なる場合は、`choiceOptionsByQuestion` のキーが21〜24の実際の問題番号と一致していることを確認する。
- `answer` には正解記号ではなく、`labels` の記号に対応する選択肢の文言または計算結果を入力する。
- 問21〜24も `explanation` を確認しないため、この一括反映では未完成として扱い、各itemに `// rev` を付けない。既存の `rev` がある場合も削除する。

### 5. 問25〜30の `QuestionTemp1` を反映する

- 各コンポーネントの `questionNumber` とPDFの設問番号を照合する。
- `questionTitle` に設問タイトルを入力する。
- 解答表の正解記号を `correctAnswer` に入力する。
- 問題文の指示が「誤っているものを選ぶ」の場合は、`answerPrompt="誤っている選択肢を1つ選んでください"` が設定されていることを確認する。
- `contents` はア・イ・ウの順であることを確認する。
- 問25のような「正しいものを1つ選ぶ」問題は、解答表の正解記号に対応する位置だけを `正しい` とし、残り2つは `''` の空欄にして行末へ `//p` を付ける。
- 問26〜30のような「誤っているものを1つ選ぶ」問題は、解答表の正解記号以外の2つを `正しい` とし、正解記号に対応する誤りの位置は `''` の空欄にして行末へ `//p` を付ける。
- この一括反映では、問25〜30の訂正内容や解説を作成しない。既存のテンプレートに具体的な訂正内容が残っている場合も、別途解説作成の指示がなければ上記の空欄形式に統一する。
- 問題文の指示と `correctAnswer`、`contents` の正誤関係が矛盾していないことを確認する。
- 問25〜30は解答表を反映しただけでは未完成として扱い、`// rev` を付けない。既存の `rev` がある場合も削除する。

### 6. 問31〜50の `QuestionTemp2` を反映する

- `items` の各オブジェクト末尾にある問題番号コメント（例: `//31`）を正本として、PDF上の問題番号と対応付ける。
- `correctAnswers` の各値を、問31〜50の解答表と問題番号順に照合する。
- 問31〜40は正誤問題として扱う。各itemの `questionTitle` を入力する。
- 解答表で「正」の問題だけ `content: '正しい'` とし、itemの先頭に `// rev: YYYY-MM-DD 確認済み` を置く。`content` 行末の `//p` は削除する。
- 解答表で「誤」の問題は `content: ''` の空欄とし、行末へ `//p` を付ける。訂正内容や解説は入力・流用せず、`// rev` も付けない。既存の具体的な訂正内容や `rev` がある場合も削除する。
- 問41〜50は組み合わせ問題として扱う。問題ごとの選択肢を `choiceOptionsByQuestion` に入力し、正解記号を `correctAnswers` の対応位置に反映する。
- 問41〜50のitemでは、正解記号に対応する選択肢文言を `content` に入力する。選択肢が `A―` または `B―` で始まる場合は、既存ファイルの表示形式に合わせて接頭辞を除いた文言を入れる。
- 正解が `オ` の「C（A・Bともに正しい）」である場合は、既存の計理ファイルの形式に合わせ、通常は `content` を空欄のままにする。
- 問41〜50は番号ずれが起きやすいため、「問題番号 / 解答表の記号 / PDFの設問タイトル / VueのquestionTitle / correctAnswers / content」を1問ずつ再確認する。
- 問41〜50は、確認が完了した各itemの先頭に `// rev: YYYY-MM-DD 確認済み` を置く。

## `QuestionTemp4` の `explanation` の扱い

- 問1〜10および問21〜24の `explanation` は、この一括反映では編集しない。
- テンプレートに既存の解説がある場合は、内容が当年度の問題と一致するかどうかにかかわらず、そのまま残す。
- 空欄の場合も新規作成しない。
- 解説の作成・修正は、ユーザーから別途明示的に依頼された場合にのみ行う。

## 進捗表の更新

- `docs/memo/生命保険講座/Keiri-progress.md` を更新する。
- `// rev` がある管理単位だけを完了として集計する。
- `QuestionTemp4` の問1〜10と問21〜24は、この一括反映では `rev` を付けないため未完了として数える。
- `QuestionTemp3` の問11〜15と問16〜20は、各大問の `contents` 配列にある `rev` を1問として数える。PDF上の5問としては数えない。
- `QuestionTemp1` の問25〜30は一括反映時点では `rev` を付けないため未完了として数える。
- `QuestionTemp2` の問31〜40は、解答表で「正」となり `content: '正しい'` と `rev` があるitemだけを1問として数える。「誤」の問題は未完了として数える。
- `QuestionTemp2` の問41〜50は、各itemの `rev` を1問として数える。
- 対象年度・フォームの実際の構成から管理単位の分母を確定する。通常は42だが、既存の構成が異なるファイルでは実数を用いる。
- 更新日時、全体の対象ファイル数・換算問題数・完了数・進捗率、対象ファイルの行、未完了一覧を更新する。
